# Quran Management & Memorization System

## ملخص المشروع

> نظام إدارة وتحفيظ القرآن الكريم — تطبيق موبايل للمعلمين والإداريين لإدارة الطلاب وتتبع_progress في حفظ القرآن.

---

## 1. ما هذا المشروع؟

**في جملة واحدة:** تطبيق موبايل يساعد معلمي القرآن على إدارة الطلاب، تتبع تقدم الحفظ، جدولة الدروس، تقييم التلاوة، وإنشاء تقارير.

**تشبيه:** تخيّل تطبيق إدارة مدرسة، لكن بدلاً من تتبع درجات الرياضيات، يتتبع أيّ سور وأيات حفظها كل طالب، وكيف تلا، وهل حضر الدرس أم لا.

### المميزات الرئيسية:
- تسجيل أول مدير (Admin) عند أول تشغيل
- إضافة طلاب (اسم، عمر، هاتف، بيانات ولي الأمر)
- إنشاء **جلسات** تسجيل: الحضور، ما تم حفظه، ما تم مراجعته، التقييمات (حفظ، تجويد، سلاسة، دقة)
- تحديد **أهداف** حفظ (مثل: حفظ سورة البقرة)
- إنشاء **جداول** للدروس القادمة
- تتبع **نطاقات الحفظ** مع نظام مراجعة دورية ( كل 7 أيام)
- حساب مستوى الطالب تلقائياً (مبتدئ / متوسط / متقدم)
- **لوحة تحكم** (Dashboard) تُظهر إحصائيات رئيسية
- **نسخ احتياطي / استعادة** لجميع البيانات بصيغة JSON

## 2. التقنيات المستخدمة (Tech Stack)

| الفئة | التقنية | الوظيفة |
|---|---|---|
| **اللغة** | **Dart** | لغة البرمجة (مثل Python أو JavaScript) |
| **إطار العمل** | **Flutter** | إطار عمل من Google لبناء تطبيقات تعمل على Android, iOS, Web, Desktop من كود واحد |
| **إدارة الحالة** | **Riverpod** (`flutter_riverpod`) | نظام لإدارة بيانات التطبيق — مثل حافظة ذكية يمكن لكل جزء من التطبيق القراءة منها والكتابة إليها |
| **التنقل** | **GoRouter** (`go_router`) | إدارة أي شاشة تظهر بناءً على المسار (مثل URLs) |
| **قاعدة البيانات** | **Drift** (SQLite) | غلاف آمن أنواعاً فوق SQLite — قاعدة بيانات محلية تعيش على الجهاز |
| **نماذج البيانات** | **Freezed** | يُنشئ تلقائياً فئات بيانات غير قابلة للتغيير |
| **تسلسل JSON** | **JsonSerializable** | يُنشئ تلقائياً كود تحويل الكائنات إلى/من JSON |
| **الرسوم المتحركة** | `flutter_animate`, `shimmer` | تجعل التطبيق أنيقاً بانتقالات سلسة |
| **الرسوم البيانية** | `fl_chart` | عرض رسوم بيانية في التقارير |
| **التشفير** | `crypto` (SHA-256) | تشفير كلمات المرور بالملح قبل التخزين |
| **الترجمة** | `flutter_localizations`, `intl` | دعم اللغة العربية واتجاه RTL |
| **المنصات المستهدفة** | Android, iOS, Web, Windows, macOS, Linux | يعمل على جميع الأجهزة |

### تشبيه الطبقات (Restaurant Analogy)

```
┌─────────────────────────────────────────────────────┐
│  Features/Presentation Layer  (غرفة الطعام)         │
│  → تعرض الطعام للزبون (الشاشات، أزرار، نماذج)     │
├─────────────────────────────────────────────────────┤
│  Domain Layer  (كتاب الوصفات)                       │
│  → يعرّف ما هي الوصفة والعمليات (لكنه لا يلمس المطبخ) │
├─────────────────────────────────────────────────────┤
│  Data Layer  (المطبخ الفعلي)                        │
│  → يُطبخ فعلياً (يستعلم من قاعدة البيانات)          │
├─────────────────────────────────────────────────────┤
│  Core  (المستلزمات المشتركة)                        │
│  → سكاكين، أطباق، توابل — تُستخدم في كل مكان       │
└─────────────────────────────────────────────────────┘
```

### الأنماط المعمارية المستخدمة

| النمط | أين يُستخدم | لماذا |
|---|---|---|
| **Repository Pattern** | `domain/repositories/` (واجهات) + `data/repositories/` (تطبيقات) | يفصل "ما بيانات أحتاجها؟" عن "كيف أحصل عليها؟" |
| **DAO Pattern** | `data/local/database/daos/` | كل جدول له كلاس مخصص للاستعلامات |
| **Dependency Injection** | `providers.dart` + Riverpod | توصيل مركزي — التطبيق يُنشئ قاعدة البيانات واحدة، ثم DAOs، ثم Services، ثم Repositories |
| **Feature-based Organization** | `features/` | كل ميزة لها مجلد `screens/` و `providers/` خاص بها |
| **Auto-disposing Providers** | `FutureProvider.autoDispose` | البيانات تُنظّف تلقائياً عندما لا تُستخدم (توفير الذاكرة) |

## 4. قاعدة البيانات (Database)

### التقنية: SQLite عبر Drift

**تشبيه:** SQLite مثل خزانة ملفات تعيش داخل التطبيق على هاتفك. Drift مثل أمين مكتبة ذكي يعرف بالضبط أين كل ملف ويمكنه إيجاده بسرعة.

**مسار الملف:** `<app-documents-directory>/quran_management.db`

### الجداول (12 جدول)

```
┌──────────────────────────────────────────────────────────────────┐
│                      جداول قاعدة البيانات                         │
├──────────────────────┬───────────────────────────────────────────┤
│ الجدول               │ الوصف                                     │
├──────────────────────┼───────────────────────────────────────────┤
│ Users                │ حسابات المعلمين/المديرين                   │
│                      │ → username, passwordHash (SHA-256+salt)   │
│                      │ → fullName, role (Admin/Teacher)          │
├──────────────────────┼───────────────────────────────────────────┤
│ Surahs               │ السور الـ 114 (محملة مسبقاً)              │
│                      │ → number, name (عربي), ayahCount         │
├──────────────────────┼───────────────────────────────────────────┤
│ JuzSurahRanges       │ ربط الأجزاء بالسور والآيات (محمل مسبقاً)  │
│                      │ → juzNumber, surahId, fromAyah, toAyah   │
├──────────────────────┼───────────────────────────────────────────┤
│ Students             │ الطلاب المسجلون                           │
│                      │ → fullName, age, phone, address,          │
│                      │ → parentName, currentSurahId, level       │
├──────────────────────┼───────────────────────────────────────────┤
│ Sessions             │ سجلات جلسات الدرس                        │
│                      │ → studentId, date, time, attendanceStatus │
├──────────────────────┼───────────────────────────────────────────┤
│ SessionMemorizations │ ما تم حفظه في كل جلسة                     │
│                      │ → sessionId, surahId, fromAyah, toAyah   │
├──────────────────────┼───────────────────────────────────────────┤
│ SessionRevisions     │ ما تم مراجعته في كل جلسة                  │
│                      │ → sessionId, surahId, fromAyah, toAyah   │
├──────────────────────┼───────────────────────────────────────────┤
│ SessionEvaluations   │ درجات كل جلسة                             │
│                      │ → memorizationScore, tajweedScore,        │
│                      │ → fluencyScore, accuracyScore             │
├──────────────────────┼───────────────────────────────────────────┤
│ Schedules            │ الدروس المخططة القادمة                     │
│                      │ → studentId, date, time, targets,         │
│                      │ → isCompleted                             │
├──────────────────────┼───────────────────────────────────────────┤
│ Goals                │ أهداف الحفظ                               │
│                      │ → studentId, title, goalType, status      │
├──────────────────────┼───────────────────────────────────────────┤
│ MemorizedRanges      │ نطاقات الحفظ الدائمة لكل طالب             │
│                      │ → studentId, surahId, fromAyah, toAyah   │
│                      │ → status, revisionCycleDays, nextReview   │
├──────────────────────┼───────────────────────────────────────────┤
│ PendingChanges       │ طابور المزامنة (المستقبلي — غير مفعّل)     │
│                      │ → entityType, operation, payload (JSON)   │
└──────────────────────┴───────────────────────────────────────────┘
```

## 5. تدفق البيانات (Data Flow)

### الرحلة الكاملة للبيانات

**تشبيه:** تخيّل نظام تنقية مياه:
```
المياه الخام = إدخال المستخدم (نقر الأزرار، ملء النماذج)
    │
    ▼
محطة المعالجة = المنطق Geschäfts (Services, Repositories)
    │
    ▼
خزان المياه النظيفة = قاعدة البيانات SQLite
    │
    ▼
أنابيب المنازل = إدارة الحالة (Riverpod Providers)
    │
    ▼
الصنبور = شاشات الواجهة التي يراها المستخدم
```

### التدفق التفصيلي

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   المستخدم   │────►│   الشاشة     │────►│   Provider   │
│  (ينقر/يملا) │     │  (Screen)    │     │  (Riverpod)  │
└──────────────┘     └──────────────┘     └──────┬───────┘
                                                  │
                                                  ▼
                     ┌──────────────┐     ┌──────────────┐
                     │   Database   │◄────│  Repository  │
                     │  (SQLite)    │     │              │
                     └──────────────┘     └──────▲───────┘
                                                  │
                                                  ▼
                     ┌──────────────┐     ┌──────────────┐
                     │     DAO      │◄────│   Service    │
                     │ (Drift ORM)  │     │ (Business    │
                     └──────────────┘     │   Logic)     │
                                          └──────────────┘
```

### مثال عملي: إنشاء جلسة

```
1. المستخدم يضغط "جلسة جديدة" ويملأ:
   ├── التاريخ والوقت
   ├── حالة الحضور
   ├── تفاصيل الحفظ (سورة 2، آيات 1-50)
   ├── تفاصيل المراجعة
   └── الدرجات (حفظ، تجويد، سلاسة، دقة)
           │
           ▼
2. SessionCreateScreen يستقيم النموذج
           │
           ▼
3. SessionDao.insert() → يُنشئ صف في جدول Sessions
           │
           ▼
4. SessionDao.upsertMemorization() → يُنشئ صف SessionMemorization
   SessionDao.upsertRevision()    → يُنشئ صف SessionRevision
   SessionDao.upsertEvaluation()  → يُنشئ صف SessionEvaluation
           │
           ▼
5. ProgressService.syncStudentProgress() →
   ├── يقرأ جميع جلسات الطالب
   ├── يحسب أي سور حفظها
   ├── يعدّ الأجزاء المكتملة
   └── يُحدّث مستوى الطالب (مبتدئ/متوسط/متقدم)
           │
           ▼
6. MemorizedRangeService.syncFromSession() → يُحدّث نطاقات الحفظ
           │
           ▼
7. ref.invalidate(sessionListProvider) → يُخبر Riverpod: "البيانات قديمة، أعد التحميل"
           │
           ▼
8. قائمة الجلسات تُحدّث تلقائياً بالبيانات الجديدة
```

### مثال عملي: تحميل لوحة التحكم

```
1. DashboardScreen يراقب dashboardProvider
           │
           ▼
2. dashboardProvider يستدعي DashboardRepositoryImpl.getDashboardData()
           │
           ▼
3. DashboardService.getDashboardData() →
   ├── يعدّ إجمالي الطلاب
   ├── يعدّ جلسات اليوم
   ├── يحسب نسبة الحضور
   ├── يجمع صفحات الحفظ
   ├── يجد أفضل 5 طلاب (بمتوسط التقييم)
   └── يحسب الحضور الأسبوعي
           │
           ▼
4. يُرجع DashboardData entity
           │
           ▼
5. DashboardScreen يعرض KPI cards + أفضل الطلاب + آخر الجلسات
```

## 7. المراجعة المتباعدة (Spaced Repetition)

```
┌──────────────────────────────────────────────────────────────┐
│  عند حفظ محتوى جديد:                                        │
│  ────────────────────                                        │
│  MemorizedRange يُنشأ بـ:                                    │
│    status = "Memorized"                                      │
│    nextReviewDate = اليوم + 7 أيام                           │
│                                                              │
│  عند عرض شاشة الحفظ:                                         │
│  ──────────────────                                          │
│  MemorizedRangeService.getByStudent() يتحقق:                 │
│    إذا nextReviewDate < اليوم ──► status = "Needs Revision"  │
│                                                              │
│  عند المراجعة:                                                │
│  ─────────────                                               │
│  markRevised() يُعيد ضبط الموقّت لـ 7 أيام أخرى             │
│                                                              │
│  النتيجة: المحتوى يُراجع بشكل دوري تلقائياً                 │
└──────────────────────────────────────────────────────────────┘
```

│  الملف: quran_backup_<التاريخ>.json                          │

## 9. دليل للمبتدئين في تتبع الكود

### كيف أجد ميزة معينة؟

```
ال想找 ميزة معينة؟ ابحث في features/

مثال: أريد تعديل شاشة الطلاب
  → features/students/
    ├── screens/
    │   ├── student_list_screen.dart     # قائمة الطلاب
    │   ├── student_create_screen.dart   # إنشاء طالب جديد
    │   └── student_detail_screen.dart   # تفاصيل الطالب
    └── providers/
        └── student_providers.dart       # مزودات البيانات
```

### كيف أجد جدول معين في قاعدة البيانات؟

```
ابحث في data/local/database/tables/

مثال: جدول Sessions
  → data/local/database/tables/sessions_table.dart
```

### كيف أجد استعلام معين؟

```
ابحث في data/local/database/daos/

مثال: استعلامات الجلسات
  → data/local/database/daos/session_dao.dart
```

### كيف أجد منطق أعمال معين؟

```
ابحث في domain/services/

مثال: حساب تقدم الطالب
  → domain/services/progress_service.dart
```

### كيف أجد تعريف نموذج معين؟

```
ابحث في domain/entities/

مثال: نموذج الطالب
  → domain/entities/student.dart
```
